# 4.1.1. Evaluación y elección del sistema de gestión de base de datos relacional

## Criterios de evaluación

La selección del SGBD relacional se realizó evaluando tres alternativas ampliamente utilizadas en entornos empresariales y académicos: **Microsoft SQL Server**, **MySQL** y **Oracle Database**. Los criterios de evaluación consideran las necesidades específicas de **RutaAcadémica** descritas en los requisitos no funcionales (sección 2.2.2) y las reglas de negocio (sección 2.2.3).

| Criterio | Descripción | Peso |
|---|---|---|
| **Soporte de transacciones y concurrencia** | Capacidad para garantizar atomicidad (RNF-04) y soportar 500 usuarios concurrentes (RNF-01). | Alto |
| **Integridad referencial y restricciones** | Soporte nativo de claves foráneas, constraints CHECK, y triggers necesarios para las 27 entidades del modelo. | Alto |
| **Rendimiento en consultas complejas** | Capacidad de ejecutar consultas con múltiples joins en tiempo ≤ 3 s (RNF-02). | Alto |
| **Seguridad y control de acceso** | Control de acceso por rol (RNF-05) y cifrado en reposo y en tránsito (RNF-06). | Alto |
| **Auditoría nativa** | Mecanismos integrados de trazabilidad para RNF-08. | Medio |
| **Compatibilidad con herramientas del equipo** | Compatibilidad con VS Code ERD Editor y ecosistema de desarrollo del equipo. | Medio |
| **Licenciamiento y costo** | Disponibilidad de edición gratuita adecuada para el contexto académico. | Medio |
| **Facilidad de administración** | Interfaz gráfica, documentación y soporte en español. | Bajo |

## Decisión

**Se elige Microsoft SQL Server** (edición Developer, gratuita para uso no productivo) como sistema de gestión de base de datos relacional de **RutaAcadémica**.

### Justificación

1. **Tipos de datos alineados con el modelo:** SQL Server ofrece `IDENTITY(1,1)`, `TIME`, `BIT`, `VARCHAR(MAX)` y `DATETIME`, que se corresponden exactamente con los tipos definidos en la sección 3.2.1–3.2.5. No es necesario adaptar la sintaxis del DDL.
2. **Aislamiento de transacciones configurable:** el modo *Read Committed Snapshot* (RCSI) permite soportar las 500 consultas concurrentes de vacantes (RNF-01) sin bloqueos de lectura, mientras que las transacciones de confirmación de matrícula utilizan el nivel *Serializable* para garantizar la atomicidad de la asignación de vacante (RNF-04).
3. **Auditoría nativa:** SQL Server Audit permite registrar todas las operaciones críticas (INSERT, UPDATE, DELETE) sobre las tablas `matricula`, `ampliacion_vacantes`, `calificacion` y `auditoria` sin código adicional, lo que cubre RNF-08.
4. **Compatibilidad con la extensión ERD Editor de VS Code:** el conector de SQL Server está soportado de forma nativa en la extensión, lo que permite generar el DDL directamente desde el diagrama físico (sección 4.2.1).
5. **Curva de aprendizaje:** el equipo trabaja con T-SQL durante el curso, lo que reduce el tiempo de onboarding y minimiza el riesgo de errores en los scripts de las secciones 4.3.1 y 4.4.1.
6. **Licencia Developer:** permite usar todas las funcionalidades de la edición Enterprise de forma gratuita en entornos de desarrollo y prueba, sin restricciones de tamaño de base de datos ni de núcleos de procesador.
